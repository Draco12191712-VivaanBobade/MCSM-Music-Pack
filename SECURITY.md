---

# Reporting a Vulnerability

If you believe you have discovered a security vulnerability, pls report it responsibly.

**Please do not disclose security vulnerabilities publicly until they have been investigated and resolved.**

When reporting a vulnerability, include as much information as possible, such as:

- A description of the vulnerability
- Steps to reproduce the issue
- The affected version(s)
- The potential impact
- Proof-of-concept code (if applicable)
- Any suggested mitigations or fixes

Reports with clear reproduction steps are much easier to investigate.

---

# How to Report

Please report vulnerabilities using one of the following methods:

- GitHub Security Advisories (preferred, if enabled)
- GitHub Issues (only if the vulnerability is **not** sensitive)
- Email the project maintainer (if an email address is provided)

If none of these options are available, please contact the project maintainer through an appropriate private communication channel.

---

# What to Expect

After receiving a report, the project maintainers will typically:

1. Acknowledge receipt of the report.
2. Investigate the issue.
3. Determine the severity and impact.
4. Develop and test a fix.
5. Release a security update when appropriate.
6. Publicly disclose the vulnerability after a fix has been made available.

Response times may vary depending on the complexity and severity of the issue.

---

# Scope

This policy applies to the source code and officially maintained releases of this project.

Issues resulting from unsupported versions, third-party modifications, or external dependencies may not be addressed by this project.

---

# Responsible Disclosure

Please:

- Give us a reasonable time to investigate and fix the issue.
- Avoid publicly disclosing the vulnerability before a fix is available.
- Avoid actions that could compromise user data, privacy, or system availability.

---

# Security Best Practices

You should:

- Download releases only from official sources.
- Follow this project's documentation and recommended configuration.

---

# Security Updates

Security fixes will be included in future releases whenever possible.

If a vulnerability is determined to be critical, an update may be released as soon as reasonably possible.
